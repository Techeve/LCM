# Setting up your SSH key

To sign in to the servers managed by LCM you need a **key pair**: a private key
that stays with you, and a public one that LCM distributes to the servers.

There are two routes - both work:

- **LCM generates the key for you.** You download the private key once.
  Convenient, but the key travelled briefly.
- **You generate it yourself** and give LCM only the public part. The private
  key never leaves your machine. This is the safer route.

> The private key is like your house key: it belongs to you alone. Never pass
> it on - not to colleagues, not to support.

## Linux and macOS

### Generate your own key

```bash
ssh-keygen -t ed25519 -C "first.last@company.com"
```

You can accept the suggested location with Enter. Do set a **passphrase** - it
protects the key should your machine go missing.

Afterwards two files live in `~/.ssh/`:

| File | Contents | Share it? |
|---|---|---|
| `id_ed25519` | private key | **never** |
| `id_ed25519.pub` | public key | yes, paste it into LCM |

Show the contents of the `.pub` file and paste all of it into LCM:

```bash
cat ~/.ssh/id_ed25519.pub
```

### Store a key generated by LCM

If LCM generated the key for you, save the downloaded file in `~/.ssh/` and fix
the permissions - without that, OpenSSH refuses to use it:

```bash
mv ~/Downloads/id_ed25519_USER ~/.ssh/
chmod 600 ~/.ssh/id_ed25519_USER
```

### Connecting

```bash
ssh -i ~/.ssh/id_ed25519_USER user@server
```

So you do not have to name the key every time, add the server to
`~/.ssh/config`:

```
Host myserver
  HostName 10.0.0.5
  User user
  IdentityFile ~/.ssh/id_ed25519_USER
```

After that, `ssh myserver` is enough.

## Windows with OpenSSH

Windows 10 and 11 already ship OpenSSH - no extra program needed. Open
**PowerShell**.

### Generate your own key

```powershell
ssh-keygen -t ed25519 -C "first.last@company.com"
```

The files end up in `C:\Users\<name>\.ssh\`. Show the public key and paste it
into LCM:

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub
```

### Store a key generated by LCM

Move the downloaded file to `C:\Users\<name>\.ssh\`. Unlike on Linux, what
matters here is not the file mode but the **owner**: the file must belong to
you and to nobody else. If OpenSSH complains about permissions, run in
PowerShell:

```powershell
icacls $env:USERPROFILE\.ssh\id_ed25519_USER /inheritance:r /grant:r "$($env:USERNAME):(R)"
```

### Making it the default

Create the file `C:\Users\<name>\.ssh\config` (without a file extension):

```
Host myserver
  HostName 10.0.0.5
  User user
  IdentityFile ~/.ssh/id_ed25519_USER
```

To use one key for **all** connections, use `Host *`:

```
Host *
  IdentityFile ~/.ssh/id_ed25519_USER
```

So you only type the passphrase once per session, start the agent and load the
key into it:

```powershell
Set-Service ssh-agent -StartupType Automatic
Start-Service ssh-agent
ssh-add $env:USERPROFILE\.ssh\id_ed25519_USER
```

## Windows with PuTTY

PuTTY uses its **own key format** (`.ppk`), which OpenSSH - and therefore LCM -
does not read directly. That is no obstacle; you just need to know which part
goes where.

### Using an existing PPK key with LCM

LCM only ever needs the **public** part. You can extract it from your existing
key without generating anything new:

1. Start **PuTTYgen** (ships with PuTTY).
2. Click *Load*, pick your `.ppk` file, enter the passphrase.
3. The box at the top labelled **"Public key for pasting into OpenSSH
   authorized_keys file"** holds your public key in the right format. Select
   and copy **all** of it - it starts with `ssh-ed25519` or `ssh-rsa` and is a
   single long line.
4. Paste it into LCM as an SSH key on your user.

> Do **not** use the contents of the `.ppk` file, nor what *Save public key*
> writes: that is PuTTY's own format, spanning several lines and starting with
> `---- BEGIN SSH2 PUBLIC KEY ----`. LCM cannot use it.

### Making it the default

There are two ways to have PuTTY use the key on its own:

**Route 1 - Pageant (PuTTY's key agent).** It keeps the key unlocked so you
enter the passphrase only once:

1. Start `pageant.exe`, then *Add Key* and select your `.ppk`.
2. For autostart, put a shortcut to `pageant.exe` into the startup folder
   (`Win`+`R`, then `shell:startup`) and append the key path to the target:

```
"C:\Program Files\PuTTY\pageant.exe" "C:\Users\<name>\.ssh\mykey.ppk"
```

**Route 2 - fixed in the PuTTY session.** In PuTTY under
*Connection → SSH → Auth → Credentials*, set your `.ppk` as *Private key file*,
go back to *Session*, give it a name and click **Save**. Next time, load the
saved session.

### Converting a PPK for OpenSSH

If you want the same key in PowerShell, VS Code or Git as well, convert it once:

1. In **PuTTYgen**, open the `.ppk` via *Load*.
2. Menu *Conversions → Export OpenSSH key*.
3. Save it as `C:\Users\<name>\.ssh\id_ed25519` (no file extension).

From then on everything in [Windows with OpenSSH](#windows-with-openssh) applies
to that key.

If a server additionally has two-factor login enabled, you need a one-time code
next to your key - see
[Setting up two-factor login for SSH](/#/doku/ssh-2fa) for how to set that up.

## When it does not work

| Message | Cause |
|---|---|
| `Permission denied (publickey)` | The public key has not reached the server yet - is it stored in LCM, and is your user assigned to that server? |
| `UNPROTECTED PRIVATE KEY FILE` | Permissions too open: `chmod 600` (Linux/macOS) or fix the owner (Windows). |
| `Invalid format` / `error in libcrypto` | Most likely a `.ppk` or a PuTTY public key was pasted. Use the text from the OpenSSH box in PuTTYgen. |
| PuTTY asks for a password instead of the passphrase | PuTTY does not know the key - the session was saved without a *Private key file*, or Pageant is not running. |
